    Why this network shape?

    Input: 44 nodes. Each digit of A and B gets its own little group of switches (one-hot): A hundreds (0–1), A tens (0–9), A ones (0–9), and the same for B. Exactly 6 switches are on for any question. Digits, not raw numbers, because addition works column by column.

    Output: 23 nodes in 3 heads. C is 0–200, so we classify each digit separately: hundreds (0–2), tens (0–9), ones (0–9). Each head is a softmax, so it gives a probability for every digit.

    Hidden: 48 → 32 → 24 (ReLU). The ones digit only needs the two ones digits. The tens digit is harder: it needs the tens digits and whether the ones column carried. Stacking layers lets the network first work out the carry, then use it. With a single hidden layer of 64 it gets stuck at roughly 1 in 5 unseen sums wrong, almost all of them in the tens digit (try it). The tapering 3-layer shape gets about 99% of unseen sums right.

    Training: mini-batches of 32, Adam optimiser, learning rate easing from 0.005 down to 0.0003 over 60 epochs, light weight decay (0.001) so it learns rules instead of memorising. In total 5,095 weights and biases.
