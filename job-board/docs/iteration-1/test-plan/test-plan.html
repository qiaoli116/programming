1. When the test plan is done

Stage 2 · DesignWrite the plan

This document. Done now, from the use cases.

Stage 3 · ImplementationWrite the tests

Alongside each use case, as it is built.

Stage 4 · TestingRun and report

Run everything, record results, send bugs back.

Why plan in design? The use cases already define what "correct" means, so the plan can be written now. Writing it early checks that the design is testable (for example, that every permission rule has an API a test can call) and stops testing being squeezed into the end.

2. Scope

In scope

  • UC-01 to UC-09, including every alternative flow
  • Role and ownership permissions
  • Security basics: hashed passwords, server-side checks, parameterised queries

Out of scope (iteration 1)

  • Performance and load testing
  • Accessibility audit
  • Browsers other than Chrome
  • Email, file upload, anything deferred in Stage 1

4. Test environment and data

  • Tests run against a temporary SQLite database created for each run and loaded with the seed data: 5 employers, 8 seekers, 30 jobs, about 45 applications. It is re-seeded before every run, so a result never depends on test order.
  • Demo accounts share the password demo1234 (demo only). Tests refer to accounts by role, for example "a seeker who has applied to nothing", chosen when the seed data is written.
  • End-to-end tests start the whole app (Express serving the built React files) on a test port.

5. Entry and exit criteria

Entry: start Stage 4 when

  • All Must use cases are built
  • The app starts with one command
  • The seed script runs cleanly

Exit: Stage 4 is done when

  • Every test case in section 6 passes
  • Every test in section 7 passes
  • The manual checklist is completed
  • No known bug blocks a use case

A failure goes back to Stage 3 if the code is wrong, or to Stage 1 if the requirement was wrong.

8. Manual checklist (Stage 4)

  • Each screen matches its mockup in static-design (layout, wording, empty states)
  • Screens are usable in a narrow, phone-width window
  • Forms can be completed with the keyboard only
  • Error and confirmation messages are clear and polite
  • The demo accounts box on Sign in lists working accounts

9. Reporting

Stage 4 results are saved in the test-result folder, one file per run: date, build, pass or fail for each test case id, bugs found and their fix status.
