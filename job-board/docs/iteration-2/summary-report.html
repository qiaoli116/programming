Iteration 2 – summary report

Job board, AI match scoring · all six stages complete · Wednesday 4 November 2026

In one paragraph

Iteration 2 added AI match scoring on top of the keyword search. A seeker writes a profile, searches, and presses "Score these results"; an AI (Claude Haiku 5.5, called from the server) reads each job, derives up to five criteria from the posting and scores each one against the profile, and the app shows a score per criterion and an overall match. Sorting by match is opt-in. It went through all six stages. The final run passed all 42 items of the test plan, using a fake AI so the result can be repeated; the real model was checked by hand and scored 20 jobs in 6.3 seconds. Two weaknesses seen in that live check are open tickets, deferred to the next cycle. The prototype runs on local host only.

Goal and result

GoalAfter the keyword search returns its list, an AI reads each job, builds up to five criteria from the posting, matches them one by one against the seeker's profile, and shows a score per criterion and an overall match.
ResultGoal met All five use cases work and are tested: keep a profile, score the results, see the criteria breakdown, sort by match, and handle the cases where scoring cannot work (empty profile, one job failing, every job failing, no criteria found).
How the AI is kept safeThe AI only answers; code decides every step (a fixed workflow). Each job is scored in its own parallel lane with a 30 second limit, each answer is checked (at most five criteria, valid levels, no empty text), and the overall is computed in code. A bad answer for one job becomes "Not scored" and never spoils the others. The API key stays on the server in a git-ignored .env file.
Where it runsLocal host only, http://localhost:3000, with ANTHROPIC_API_KEY in app/.env. SCORING_PROVIDER=fake runs it with no key and no network.
StatusClosed. No maintenance is planned. Two open tickets are the starting point for iteration 3.

Live check with the real model

Twenty seeded jobs were scored against the sample profile in 6.3 seconds. Every job came back scored, with criteria taken from its own posting, and the reasons quote the profile or say it is silent. Reading the answers is a person's judgement, not a pass/fail test.

Problems found

The final run had no failures, so there was nothing to fix after testing. Reading the real model's answers showed two weaknesses, both written up as tickets and left open.

TicketFound byWhat it isProposed fixStatus
JB-003Live checkA score built from one checked criterion looks as certain as one built from five (0/10 or 10/10 from a single fact).Show "Low confidence" when fewer than 3 criteria were checked.Open – deferred
JB-004Live checkThe AI sometimes adds generic criteria (for example the cover letter) that every job has.Add one instruction to the prompt; re-run the live check.Open – deferred

Neither is a missing requirement, so nothing went back to Stage 1. Smaller things fixed while building: the level label stretched in the narrow sidebar (CSS); a browser test lost its scores by reloading the page, so it now moves around with the in-app link; the verification tool had to learn the new plan ids and the iteration 2 checklist.

Lessons

What went well

  • Putting the AI behind a small interface made the whole feature testable offline and repeatable.
  • One lane per job meant one bad answer never spoiled the list; the failure cases were designed first and tested with the fake AI.
  • The code, not the AI, computes the overall, so the score rule is explainable and tested.
  • Opt-in scoring and a privacy notice kept cost and data use in the seeker's hands.

What to change next time

  • The test-plan reader only checked ids of a fixed shape; check that the number of plan items read equals the number in the plan, so a missed item is caught at once.
  • Judge the real model's answers on a fixed set of jobs and write down the counts (how many were generic, how many had one criterion), so a prompt change can be compared.
  • Decide in Stage 2 what the overall should show when little could be checked (JB-003).
  • Commit at the end of each stage; the iteration 2 work is still uncommitted.
