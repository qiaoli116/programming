Choosing how to build an agent

A brief tutorial. Companion to agent-architecture.html.

An agent is software that calls an LLM on your behalf, possibly many times. The LLM is stateless, so every call must carry everything it needs. Whoever writes the code around those calls is "the agent". The only real question is how much of that code you write yourself.

▼ least of your own code, fastest start
Why level 5 is not recommended: ready-made agents (Claude Code, Codex). These are finished products that you, the developer, use at your own desk, to write code, edit documents or run local tasks. They are tools for building software, not building blocks for software that real users will use: end users get your product, not your coding assistant on your machine. (This project is itself built with one.) Use them to build your product, not as your product.

Levels 3 and 4 are not strictly above or below each other: an SDK gives you one good agent, a framework coordinates steps or agents. Teams often combine them.

What you write and what you get

LevelYou writeYou get for free

4 Framework (e.g. LangGraph)The graph, the nodes, the stateOrchestration, branching, retries, saved state, often many providers
5 Ready-made agentNothing; you just use itA finished agent for developers (not recommended for end-user products)

The key difference: who decides the next step?

This is what "agentic" means. From level 2 on the LLM chooses what happens next. That is where cost, risk and unpredictability grow, and where tests get harder (at level 1 you can fake the LLM and test your code exactly).

How to choose: ask in this order

Are the steps known in advance?
Yes → no agent loop needed. Level 0 or 1: cheaper, faster, predictable, easy to test.
No, the model must explore (open web research, many files) → level 2 or higher.
Is the work for you, the developer, on your own machine? (writing code, editing documents, local automation) → just use a ready-made agent such as Claude Code or Codex; there is nothing to build. Is it for your product's users? → build one with levels 1 to 4 (level 5 is not recommended). If you need a Claude Code-like agent inside your product, use level 3 (an agent SDK).
Is it part of your own product, running on your server? → level 1, 2 or 3, depending on question 1.
Does it need several coordinated steps, branches, human approval pauses, or progress saved across hours? → a framework (level 4), or an SDK that offers it.
Must you be able to switch model providers? → a framework, or your own thin interface (level 1 or 2).
How much control do you need? Exact prompts, limits and tests → lower levels. Speed to a working result → higher levels.

Rules of thumb

  • Start at the lowest level that works. Move up only when you feel a specific pain, such as rewriting a loop, trimming history, or adding retries.
  • Don't rebuild a general loop that someone has built well. The hard parts are context limits, tool errors, permissions and cancelling, not the loop itself.
  • Don't use a loop for a fixed pipeline. Autonomy adds cost and risk and removes repeatability.
  • Frameworks add concepts to learn (graphs, state). They pay off when orchestration is the hard part, not when the job is one prompt.

Where our job board lands

Level 1: a fixed workflow written from scratch. Load the profile and jobs, build one prompt per job, run all calls in parallel, check each answer, compute the score ourselves, reply. See the flowchart.

  • The steps are known in advance, so the LLM never needs to choose one.
  • Our code checks the answer and does the arithmetic; the LLM only reads and explains.
  • Tests use a fake LLM and are exact (see the AI provider decision).
  • A class can see every piece, with no framework hiding it.

Summary

  • An agent is your software calling a stateless LLM, perhaps many times.
  • The ladder: one call → fixed workflow → own loop → SDK → framework. Ready-made agents (Claude Code, Codex) are tools for developers, not part of the ladder.
  • The deciding question: who decides the next step, your code or the LLM?
  • Pick the lowest level that does the job. We chose level 1 because our steps never change.
